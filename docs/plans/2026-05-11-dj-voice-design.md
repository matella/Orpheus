# DJ Voice — Phase 2 Design

**Date:** 2026-05-11
**Branch:** feature/dj-voice (to be cut from feature/dj-curator)
**Depends on:** DJ Curator Phase 1 (patter text in curator_update)

## Summary

Convert the patter text already generated by Phase 1 into spoken audio using Piper TTS. The Flutter client orchestrates the full lifecycle: duck Spotify volume → fetch WAV from server → play → restore volume. Server wraps Piper as a subprocess behind an abstract adapter interface.

## Key Decisions

| Decision | Choice | Rationale |
|---|---|---|
| TTS engine | Piper | Fast (~100ms for short patter on CPU), single binary, Windows support, simple subprocess integration |
| Audio delivery | HTTP pull (client fetches WAV) | Client already has patter text from WS; on-demand keeps curator pipeline clean, no temp files |
| Volume ducking | Client-orchestrated | Client knows exact playback start/end; avoids duration estimation on server |
| Generation timing | On-demand | Piper is fast enough; patter plays after track starts, natural 1–2s window available |

## Architecture

```
curator_update (WS, has patter text)
        │
        ▼
  Flutter client (TtsService)
        │
        ├─ PUT /api/playback/volume  (duck to tts_duck_volume%)
        ├─ GET /api/tts/speak?text=… (returns WAV bytes)
        │        │
        │        ▼
        │   Node.js TTS route
        │        │
        │        ▼
        │   piper.ts — spawns Piper binary
        │              stdin ← patter text
        │              stdout → WAV bytes
        │
        ├─ just_audio plays WAV
        └─ PUT /api/playback/volume  (restore on complete)
```

## Server

### New Files

**`server/src/tts/adapter.ts`**
Abstract interface:
```typescript
export interface Voice { id: string; name: string; }
export interface TtsAdapter {
  speak(text: string): Promise<Buffer>;
  listVoices(): Promise<Voice[]>;
  isAvailable(): boolean;
}
```

**`server/src/tts/piper.ts`**
Piper implementation:
- Spawns `piper.exe --model <voice>.onnx --output_file -`
- Writes patter text to stdin, captures WAV from stdout
- 10s timeout (matches Spotify token refresh timeout pattern)
- `isAvailable()` checks binary exists at `PIPER_BINARY_PATH`
- On non-zero exit or timeout: throws `AiError`

**`server/src/api/routes/tts.routes.ts`**

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/tts/speak?text=…` | Returns `audio/wav` bytes for given text |
| `GET` | `/api/tts/voices` | Lists `.onnx` files in `PIPER_VOICES_DIR` |
| `POST` | `/api/tts/preview` | `{ voiceId }` → WAV of sample phrase |
| `PUT` | `/api/tts/settings` | `{ ttsEnabled, ttsVoice, ttsDuckVolume }` → persists to DB |

All TTS routes return 503 with `{ error: 'tts_unavailable' }` when Piper is not installed — client silently skips audio, patter text still shows in banner.

## Client

### New Files

**`client/lib/services/tts_service.dart`**
Encapsulates the full audio lifecycle:
```dart
Future<void> speakPatter(String text, double duckVolume) async {
  await apiService.setVolume((duckVolume * 100).round());
  final player = AudioPlayer();
  await player.setUrl('$baseUrl/api/tts/speak?text=${Uri.encodeComponent(text)}');
  await player.play();
  await player.processingStateStream
      .firstWhere((s) => s == ProcessingState.completed);
  await player.dispose();
  await apiService.restoreVolume();
}
```
Skipped entirely when:
- `chattiness == 'silent'`
- `ttsEnabled == false`
- Patter text is empty
- Server returns 503 (Piper not installed)

## Graceful Degradation

- Piper binary not installed → `isAvailable()` = false → all TTS routes return 503 → client skips audio silently, patter text still displayed
- Piper times out → `AiError` thrown → route returns 503 → same client behavior
- `just_audio` playback error → `.catchError` in home_screen swallows it → no crash
- `chattiness == 'silent'` → `TtsService.speakPatter` is never called
- `ttsEnabled == false` → `TtsService.speakPatter` is never called
